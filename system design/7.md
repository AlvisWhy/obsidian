Data quality desgin
completeness: assertion on row count (We compare the rows with the previous one)
null-rate check on key col
```python
SELECT 
	COUNT(*)
	COUNT(*) - COUNT(customer_id)
	ROUND(100* (COUNT(*) -  - COUNT(customer_id))/ COUNT(*),1) 
	AS null_pct
FROM orders
HAVING null_pct>1


```
validations
```SQL
order_total BETWEEN 0 AND 10000

status IN ('placed', 'shipped', 'cancelled')

email ~ '^[^@]+@[]...'

```
uniqueness: distinct order_id
```SQL
-- 1 Uniqueness
SELECT order_id, COUNT(*) AS n
FROM orders
GROUP BY order_id
HAVING COUNT(*) > 1

-- 2 Referential integrity: orphand fact rows
SELECT o.order_id
FROM order o
LEFT JOIN dim_customer c ON o.customer_id = c.customer_id
WHERE c.customer_id IS NULL

```
timeliness: data is fresh within a time period
```SQL
MAX(event_ts) > now() - interval
```

Data contract

A schema change must bump the version. Not silently break

```python
from pydantic import BaseModel Field
from decimal import Decimal
from typing import Literal

class OrderEvent(BaseModel):
	"""owner: orders-team    version: 2.1"""
	order_id: str                          
	customer: str
	amount: Decimal = Field(ge = 0)
	status: Literal['placed', 'shipped', 'cancelled']
	time_stamp: str
	# SLA freshness < 1h, completeness > 99.9%
```
